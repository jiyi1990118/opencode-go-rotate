# go-rotate × zen-gateway 渐进整合设计方案

> 日期：2026-08-16
> 性质：**只读分析报告**（不写任何代码），作为并行开发 teams 的契约
> 原则：**渐进整合，各自保留核心**——不合并进程、不重写 gateway.mjs 协议层、不改插件注入机制、不引入 npm 依赖。

---

## 1. 背景与目标

现状：`go-rotate`（插件 + CLI + Web，端口 8899）与 `zen-gateway`（OpenAI/Anthropic/Responses 网关，端口 18888）是两个独立交付物，共用 `go-keys.json` / `auth.json` / 文件锁 / 日志，但**管理面完全割裂**：

- CLI 只管理 key，不知道网关存在（`go-rotate status` 不显示网关状态）。
- Web 面板仅有一个只读的「zen-gateway 状态」卡片（`gatewayStatus()` 拉 healthz+usage），**不能启停、看不到模型、看不到网关日志**。
- 安装要分两次（`install.sh` 装插件+CLI，`bash install.sh zen-gateway` 装网关服务），卸载也要分别处理。

用户已确认目标（渐进整合）：

1. **CLI 统一**：`go-rotate gateway start|stop|restart|status|logs` 子命令（Python 封装，复用 bash 管理脚本逻辑）；`go-rotate status` 末尾追加网关状态一行。
2. **Web 网关管理**：8899 面板「网关管理」卡片——运行状态（复用现有 `gatewayStatus`）、启动/停止/重启按钮、模型列表、日志尾部。需要 gateway 侧新增**只读管理端点**（`GET /api/gateway/status`、`GET /api/gateway/log`）。
3. **打包**：`install.sh` 新增 `--all` 一键装插件+CLI+网关服务；CLI `uninstall` 增加可选 `--gateway` 清理网关。

## 3. 总体架构决策

| 决策 | 理由 |
|---|---|
| **网关只加只读端点**，不内嵌 start/stop | 避免「进程自杀」：网关自己 stop 自己必然失控；launchd KeepAlive 会立刻重启，语义混乱。管理权唯一归属 bash 脚本（launchd） |
| **管理操作一律走 bash 脚本**（Web 后端 execFile、CLI subprocess 转发） | 不复制 launchd 逻辑（避免三份实现漂移）；bash 脚本已幂等、带健康等待、跨 macOS/旧版回退 |
| **Web 后端代理拉取网关新端点**，浏览器不直连 18888 | ① GET 响应无 CORS 头（仅 OPTIONS 分支有）浏览器跨域会挂；② 网关设 `ZEN_GATEWAY_TOKEN` 时浏览器无法带 token；③ 保持「页面只与 8899 同源交互」的既有模式 |
| **`gatewayStatus()` 向后兼容扩展**（加可选 `meta` 字段） | 既有 `/api/gateway` 消费者与测试断言（`running`/`healthz`/`usage`/`error`）零破坏 |
| **CLI `gateway` 子命令 = bash 脚本转发**，脚本缺失给安装提示 | 渐进整合，Python 不重写 launchctl；`status` 的网关行是纯 HTTP healthz 探测，**与脚本是否安装无关** |
| **`install.sh --all` 显式开关**，不改默认行为 | 默认 `install.sh` 保持只装插件+CLI（向后兼容）；网关是常驻服务，默认装上会改变用户机器行为，须显式选择 |

## 5. 契约 / 接口定义（开发 teams 严格照此实现）

### 5.1 CLI 子命令签名（Team C 产出）

```
go-rotate gateway status                # 网关运行状态（launchd 加载 + healthz），退出码 0
go-rotate gateway start                 # 启动（脚本幂等；含健康等待），退出码透传脚本
go-rotate gateway stop                  # 停止（幂等）
go-rotate gateway restart               # 重启（stop+start）
go-rotate gateway logs [N|-f|--follow]  # 日志尾部（默认 100 行；-f 跟随）
go-rotate status                        # 末尾追加一行网关状态（HTTP 探测，与脚本无关）
go-rotate uninstall [-y] [--gateway]    # --gateway：同时清理网关服务（不动 go-keys/auth.json）
```

- 退出码：0 成功；1 脚本缺失 / 子命令未知 / 脚本非零退出（透传）。
- 输出格式：`gateway:` 前缀（与 `zen-gateway` 脚本输出风格一致，便于脚本化 grep）。

### 5.2 Web API 路由（Team B 产出，go-rotate.ts，端口 8899）

| 方法/路径 | 请求 | 响应（JSON） |
|---|---|---|
| GET `/api/gateway`（**扩展**，兼容旧字段） | - | `{running:bool, healthz?:{...}, usage?:{...}, meta?:<见 5.3 status 载荷>, error?:string}`（`meta` 仅在 running 时存在） |
| GET `/api/gateway/log` | - | `{ok:true, source:"launchd"\|"shared"\|"none", lines:number, log:string}` 或 `{ok:false, error:string}`（网关未运行/超时） |
| POST `/api/gateway/start` | `{}` | `{ok:bool, output:string, code:number\|null}`；脚本缺失/异常 → 400 `{ok:false, error:string}` |
| POST `/api/gateway/stop` | `{}` | 同上 |
| POST `/api/gateway/restart` | `{}` | 同上 |

- 管理路由**无用户输入**（固定动词），无注入面；仅 127.0.0.1 可访问（既有模式）。
- start/restart 超时 30s；execFile 超时 kill 包装进程不撤销 launchd 加载，响应 `ok:false` 但服务可能仍在启动——前端提示「操作超时，请稍后刷新」。

### 5.3 gateway 新端点（Team A 产出，gateway.mjs，端口 18888，**只读**）

```
GET /api/gateway/status → 200
{
  ok: true,
  running: true,            // 本端点由网关自己应答，恒 true
  version: "1.1.0",         // GATEWAY_VERSION
  port: 18888,              // PORT
  host: "127.0.0.1",        // HOST
  defaultModel: "hy3",      // DEFAULT_MODEL
  models: ["deepseek-v4-flash", ...],   // allModelIds()（内置∪动态，排序去重）
  dynamic: 0,               // ZEN_MODELS_DYNAMIC.length
  aliases: 18,              // Object.keys(MODEL_ALIAASES).length（可选字段）
  usageFile: "~/.local/share/zen-gateway/usage.jsonl",  // USAGE_FILE
  configFile: "~/.config/opencode/go-keys.json",        // CONFIG_FILE
  authEnabled: false,       // !!TOKEN（只给布尔，绝不泄漏 token）
  uptimeSec: 12345,
  startedAt: "2026-08-16T..."   // 可选字段
}

GET /api/gateway/log?lines=200 → 200
{ ok: true, source: "launchd"|"shared"|"none", lines: 200, log: "<尾部文本>" }
```
- `lines` 取值钳制 `[1, 1000]`，非法回退 200。
- `source` 判定：`ZEN_GATEWAY_LOG`（env）→ `~/Library/Logs/zen-gateway.log`（launchd stdout）存在 → `"launchd"`；不存在则读 `/tmp/opencode-go-rotate.log` 过滤含 `[gateway]` 的行 → `"shared"`；都没有 → `"none"`，`log:"(no log)"`。
- **只读**：端点绝不写任何文件、不触发 rotate/syncAuth/探测。
- 鉴权：与其他路由一致过 `gatewayAuth(req)`（设了 `ZEN_GATEWAY_TOKEN` 则需带 token；go-rotate.ts 后端可用 `GOROTATE_GATEWAY_TOKEN` 配合）。

## 8. 风险与注意事项

| 风险 | 缓解 |
|---|---|
| 网关设 `ZEN_GATEWAY_TOKEN` 时新端点 401 | Web 后端 `GOROTATE_GATEWAY_TOKEN` 透传（5.4）；CLI status 探测同样会 401 → 显示 not running（可接受，文档注明） |
| `execFile` start 超时（launchd spawn 慢，已知最慢 ~78s 负载高时） | 超时 30s，前端提示「操作超时请刷新」；幂等设计下重复 start 无害 |
| 管理脚本在 `~/.local/bin` 或 `~/bin` 二选一 | `resolveZenGatewayBin`/`find_zen_gateway_script` 双候选 + env 覆盖（5.4） |
| Web 模板字符串换行 | 沿用既有 `\\n` 转义纪律，`node --check` 兜底 |
| 卸载误伤真实服务 | Team D 沙箱隔离 + 集成验证只读优先（6.4/6.5） |
| 端点膨胀 / 权限边界 | 新端点只读 + 无用户输入；管理操作仅限固定动词白名单（start/stop/restart），不做任意命令 |
| 测试碰真实配置 | 6.0 红线 + md5 铁证，任何 team 违反即事故（AGENTS.md 已多次记录） |

## 9. 关键契约总结（交付 teams 速查）

1. **CLI（Team C）**：`go-rotate gateway {status|start|stop|restart|logs [N|-f]}`（Python 转发 bash 脚本，脚本缺失 exit 1 + 安装提示）；`go-rotate status` 末尾 `gateway: running|not running`（HTTP 探测）；`uninstall [-y] [--gateway]`。
2. **Web（Team B）**：`GET /api/gateway`（扩展含 `meta`）+ `GET /api/gateway/log` + `POST /api/gateway/{start,stop,restart}`（execFile 调 `ZEN_GATEWAY_BIN` 解析的管理脚本，超时 30s）；新卡片含按钮/模型列表/日志尾部；`gatewayStatus()` 旧字段不变。
3. **网关（Team A）**：只读端点 `GET /api/gateway/status`（返回 `{ok,running,version,port,host,defaultModel,models,dynamic,aliases,usageFile,configFile,authEnabled,uptimeSec,startedAt}`）+ `GET /api/gateway/log?lines=N`（返回 `{ok,source:"launchd"|"shared"|"none",lines,log}`）；加 `GATEWAY_VERSION` 常量 + `ZEN_GATEWAY_LOG` env；**不内嵌 start/stop**。
4. **安装（Team D）**：`install.sh --all`（默认安装 + `install_zen_gateway`）；`install.sh uninstall [--gateway] [-y]`；不动默认行为、不动 auth.json。
5. **依赖顺序**：A/C/D 先发，B 以 stub 并行；集成验证在 A 落地后进行。
6. **隔离红线**：真实 go-keys.json/auth.json 永不写入（md5 铁证）；bun 测试用 `GOROTATE_CONFIG_FILE/GOROTATE_AUTH_FILE`；网关测试用 `ZEN_*` 临时 env + 临时端口；管理操作测试用 `ZEN_GATEWAY_BIN` stub 脚本，不碰真实 launchd 服务。
