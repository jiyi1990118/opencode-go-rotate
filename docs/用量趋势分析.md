# 用量趋势分析（usage-report.mjs）

> 2026-08-16 新增。为 zen-gateway 的持久化用量数据 `usage.jsonl` 提供趋势分析工具，替代裸 `tail -f`。

## 背景：usage.jsonl 是什么

网关每次请求完成后（`sendWithRotation`）向 `usage.jsonl` **追加**一行 JSON，跨重启保留（持久化趋势）：

```json
{"ts":"2026-08-16T05:22:38.171Z","key":"act2","ok":true,"model":"hy3","rotated":false,"endpoint":"chat"}
```

| 字段 | 含义 |
|---|---|
| `ts` | 请求完成时间（ISO 8601，UTC） |
| `key` | 最终使用的 key 名（`rotated:true` 的行记录的是**重试后的新 key**） |
| `ok` | 最终响应是否 2xx（`true`=成功 / `false`=失败） |
| `model` | 实际映射后的上游模型（如 `hy3` / `glm-5.2` / `deepseek-v4-flash`） |
| `rotated` | 本次请求是否触发了 key 轮换 |
| `endpoint` | `chat`（OpenAI /chat/completions） / `messages`（Anthropic /v1/messages） / `responses`（OpenAI /v1/responses） |

- 默认路径 `~/.local/share/zen-gateway/usage.jsonl`，`ZEN_USAGE_FILE` 环境变量可覆盖。
- 行数上限 5000，超过后**截断保留后 1000 行**（`truncateUsageIfNeeded`），所以趋势统计是「近期」而非全历史。

## 工具用法

```bash
node zen-gateway/usage-report.mjs [--file <路径>] [--days N] [--key NAME] [--endpoint chat|messages|responses] [--json]
```

| 选项 | 说明 |
|---|---|
| `--file <路径>` | usage.jsonl 路径覆盖（默认 `~/.local/share/zen-gateway/usage.jsonl`） |
| `--days <N>` | 按日趋势窗口天数（默认 7，**仅影响趋势部分**） |
| `--key <NAME>` | 只统计指定 key（精确匹配） |
| `--endpoint <EP>` | 只统计指定端点（`chat` / `messages` / `responses`） |
| `--json` | 输出机器可读 JSON（便于接 Web / 脚本） |
| `--help` | 显示帮助 |

退出码：`0` 正常；`1` 文件不存在或为空；`2` 参数错误。

## `/api/usage/trend` 端点（2026-08-16 新增）

网关进程内直接聚合 `usage.jsonl` 的 HTTP 端点，供 Web/CLI 消费：

```bash
curl http://127.0.0.1:18888/api/usage/trend                  # 默认近 7 天
curl "http://127.0.0.1:18888/api/usage/trend?days=3"         # 近 3 天窗口
curl "http://127.0.0.1:18888/api/usage/trend?key=act1"       # 只统计指定 key
```

返回（JSON）：

```json
{
  "total": 10,
  "byKey":   { "act1": { "requests": 5, "success": 4, "fail": 1, "rotated": 0, "lastTs": "..." } },
  "byDay":   { "2026-08-16": { "requests": 4, "success": 3, "rotated": 1 } },
  "byEndpoint": { "chat": { "requests": 7, "ok": 6 }, "messages": { "requests": 2, "ok": 0 } },
  "badLines": 2,
  "window":  { "days": 7, "startUtc": "...", "endUtc": "..." }
}
```

要点：

- **数据源**：持久化 `usage.jsonl`（`ZEN_USAGE_FILE` 可覆盖），每次请求同步重读——文件 ≤5000 行（截断机制保证），无缓存即天然实时。
- **语义与 usage-report.mjs 完全一致**：坏行跳过计 `badLines`（空行不算）、`ts` 按 UTC 归日（兼容 `+08:00` 偏移）、`days` 窗口只统计近 N 天（默认 7，非法回退 7）、`key` 精确筛选、`badLines` 不受筛选影响。
- **文件不存在** → 空结构 `{total:0, byKey:{}, byDay:{}, byEndpoint:{}, badLines:0, window:{...}}`，HTTP 200（不是 404）。
- **实现**：`aggregateUsage(lines, opts)` / `readUsageFile(path)` 为 ESM 顶层 export 纯函数（与 parseResetTime 等 16 个并列），已纳入单测（16 用例）。

## 三个消费入口的区别

| 维度 | `/api/usage`（内存） | `/api/usage/trend`（HTTP 聚合） | `usage-report.mjs`（独立脚本） |
|---|---|---|---|
| 数据来源 | 进程内存 `usageStats` | 磁盘 `usage.jsonl`（进程内 readFileSync） | 磁盘 `usage.jsonl`（readline 流式） |
| 生命周期 | 重启清零 | 跨重启保留 | 跨重启保留 |
| 运行位置 | 网关进程内 | 网关进程内 | 独立 CLI（`node usage-report.mjs`） |
| 覆盖范围 | 当前进程实时累计 | 持久化趋势（可 `days`/`key` 筛选） | 持久化趋势（`--days/--key/--endpoint` 筛选） |
| 粒度 | 每 key 成功/轮换 | 每 key + 每**日** + 每端点 + 坏行 | 每 key + 每**日**（ASCII 柱状图）+ 端点 + 模型维度 |
| 失败行 | 只记 rotated，失败请求本身不计数 | 每行都记 | 每行都记 |
| 输出 | JSON（HTTP） | JSON（HTTP，供 Web/CLI 程序消费） | 文本报告 / `--json`（人工查看/离线分析） |
| 适用 | 看「此刻进程状态」 | 程序化取历史趋势（Web 图表等） | 命令行人工分析、离线归档统计 |

结论：三者为**同一份数据的不同消费形态**——`/api/usage` 看当下进程；`/api/usage/trend` 供程序实时拉历史趋势；`usage-report.mjs` 供人工离线分析（多维度+柱状图，不依赖网关运行）。

## 设计取舍

- **坏行处理**：非 JSON / 缺 `key`/`ts` 字段 / 时间不可解析的行跳过并计入 `bad_lines`（汇总显示），不中断分析；空行（文件末尾换行）不算坏行。
- **UTC 归日**：`ts` 先经 `Date` 归一再取 UTC 日期，兼容带时区偏移的 ISO（如 `+08:00` 自动折算），避免时区把同一天拆到两天。
- **筛选语义**：`--key` / `--endpoint` 作用于汇总、按 key 明细、趋势三个部分；`--days` 只作用于趋势窗口（汇总/按 key 仍基于全文件）。坏行无法归属，`bad_lines` 不受筛选影响。
- **汇总 vs 趋势**：汇总=全文件（受 key/endpoint 筛选）；趋势=近 N 天窗口（窗口内无数据的日期显示 0，可看出「无流量」）。
- **内存友好**：`node:readline` 流式逐行读取，不把整个文件载入内存（文件上限 5000 行，实际开销可忽略）。
- **只读**：工具绝不写入 usage.jsonl。
- **全坏行文件**：文件存在且非空但无任何合法行 → 输出 `bad_lines=N` + 提示「未解析到任何有效记录」，exit 0（不误报为文件问题）。

## 截断策略说明

网关在 `usage.jsonl` 超过 **5000 行**时截断为保留**后 1000 行**（`USAGE_MAX_LINES` / `USAGE_KEEP_LINES`）。因此：

- 趋势统计是「近期」而非全历史——活跃使用下大约只覆盖最近几十小时到几天。
- 若需更长历史，可定期把 `usage.jsonl` 归档（复制改名），或降低流量观察频度。
- `--days` 窗口大于数据实际跨度时，早于首条数据的日期显示 0，属正常。
