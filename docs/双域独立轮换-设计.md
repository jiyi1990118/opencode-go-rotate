# 双域独立轮换设计（TUI / 网关）

> 2026-08-17 用户需求 + brainstorming 澄清后定稿。契约文档，实施 team 必读。

## 需求

opencode TUI（插件路径）与 zen-gateway（网关代理路径）共用同一套 key（同一份 `go-keys.json`），但**两域各自独立轮换**：

1. 网关切换 key **不影响** opencode TUI 中 zen/go 套餐正常使用的 key
2. TUI 中 zen/go 套餐的 key 轮换单独设置（现状行为不变）

## Schema 演进（并列字段，向后兼容，零迁移）

```jsonc
{
  "provider_id": "opencode-go",
  "cooldown_minutes": 300,        // 共享窗口配置（两域同用，不分裂）
  "current": "act1",              // TUI 域游标（字段名不变 = 零迁移）
  "current_gateway": "act1",      // 新增：网关域游标。读侧兜底 `current_gateway ?? current`
  "keys": [{
    "name": "act1",
    "key": "sk-...",
    "cooldown_minutes": 30,          // 共享：该 key 独立窗口（两域同用）
    "cooldown_until": null,          // TUI 域冷却记录（字段名不变）
    "cooldown_until_gateway": null   // 新增：网关域冷却记录。旧值 null = 网关域干净起步
  }]
}
```

- 旧配置**无需迁移**：网关域读侧兜底初值 = TUI current；网关域冷却读 `cooldown_until_gateway`（null = 无冷却）
- `cooldown_minutes`（全局与每 key）为共享配置，**不按域分裂**

## 各组件改动面（按团队分工）

### Team A — 插件 go-rotate.ts（TUI 域 + Web 管理端）

- TUI 域轮换逻辑（rotate/pickNext/cooldownUntilDefault/chat.headers 注入）**现状不动**（它们天然只读写 `current`/`cooldown_until`）
- `Config` 接口 + loadConfig：加 `current_gateway: string`、`k.cooldown_until_gateway: string|null`；读侧兜底 `current_gateway ?? current`
- 自愈 reconcileCurrent：TUI 域查 `current`（现状）；网关域若 `current_gateway` 指向不存在 name → 兜底 `current` 或 keys[0]
- Web API：
  - `POST /api/current` 支持 body `{name, domain?: "tui"|"gateway"}`（默认 tui）：tui→写 `current`，gateway→写 `current_gateway`
  - `POST /api/cooldown` 支持 body `{name, minutes, domain?}`（默认 tui）：tui→`cooldown_until`，gateway→`cooldown_until_gateway`（minutes=null 清除对应域冷却）
  - `POST /api/rotate` 不变（仅 TUI 域；网关域手动轮换走 CLI `gateway next`）
- `statusPayload`：`current`（TUI）+ `current_gateway` + 每 key `cooldown_until`/`cooldown_until_gateway`/`isCurrent`（tui）/`isCurrentGateway`（新增字段，向后兼容保留 isCurrent）
- Web 页面：
  - 概览 6 格「当前 key」= TUI 域 current（现状）
  - 网关状态卡 `gw-current` 改显示**网关域** current（现状显示 cfg.current 需改）
  - Key 管理表「设为当前」拆 TUI/网关两枚按钮（各带 domain 参数）；冷却清除按钮同理由单枚改两枚或带域选择
- 插件单测：域分离用例（set/cooldown 各域互不影响、迁移兜底、statusPayload 双域）

### Team B — 网关 gateway.mjs（网关域）

- `loadConfig` 默认值加 `current_gateway`；读侧兜底 `current_gateway ?? current`
- `currentKey(cfg)` / `pickNext(cfg)`：起点读 `current_gateway`；冷却判定读 `k.cooldown_until_gateway`
- `rotate()`：冷却写 `k.cooldown_until_gateway`（窗口用共享 `cooldown_minutes`/`k.cooldown_minutes`）；current 写 `cfg.current_gateway`
- reconcileCurrent 自愈：查 `current_gateway`
- **🚨 关键红线：网关 rotate 不再同步 auth.json**（现状 `syncAuth` 会把 `opencode-go.key` 改写成新 key）。auth.json 单槽无法代表两域——网关域轮换绝不碰 auth.json，auth.json 仅由 TUI 插件轮换维护。这样网关切 key 不影响 TUI 持久化凭据（TUI 重启后仍用自己域 key）
- `/api/gateway/config`、`/api/gateway/status`：`current` 字段改返回网关域 current（命名可保持 `current` 避免破坏前端，值改为 current_gateway 域）
- 网关单测：域分离用例（rotate 只动网关域字段 + **auth.json md5 铁证：网关轮换后真实 auth.json 逐字节不变**）

### Team C — CLI go-rotate（Python）

- `set <name>` / `next [min]` / `cooldown <name> [min]` 默认操作 **TUI 域**（现状不变）
- 新增子命令：
  - `go-rotate gateway set <name>` → 写 `current_gateway`
  - `go-rotate gateway next [min]` → 网关域轮换（写 `current_gateway`，把原网关 current 冷却 `cooldown_until_gateway`）
  - `go-rotate gateway cooldown <name> [min]` → 写/清 `cooldown_until_gateway`（min 缺省=现状语义，null/clear=清除）
- `status` 输出双域当前 key（`TUI 当前: act1` / `网关当前: act2`）
- CLI 单测：临时 HOME 隔离全链路（set/next/cooldown 各域独立）

## 风险与边界

- **物理配额共享**：网关把 key A 用爆（429），TUI 用 A 仍会失败一次再自行轮换——符合「互不干扰」语义，两域各自独立记录失败经验
- `chat.headers` 注入 providerID 匹配逻辑不变（TUI 域 current 注入所有 opencode provider）
- Web `/api/rotate` 仅 TUI 域；网关域手动轮换用 CLI
- 测试铁律：所有测试用 `GOROTATE_CONFIG_FILE`/`GOROTATE_AUTH_FILE`/`ZEN_CONFIG`/`ZEN_AUTH_FILE`/临时 HOME 隔离，严禁碰真实 go-keys.json/auth.json/8899/18888
- Web 单测红线：`bun test tests/go-rotate-plugin.test.ts` 必须全绿（现状 107/107）
