### 1.2 信息架构问题清单（含代码依据）

| # | 问题 | 代码依据（/tmp/gr-web.html 行号） | 影响 |
|---|---|---|---|
| P1 | **概览是「数字陈列」不是「状态面板」**：冷却窗口与 Web 自动启动在概览与设置**双处出现且双处可操作**（概览带「编辑」链接 + Web 开关按钮） | L70（冷却+编辑链接）、L71、L75-76（web 按钮）；L186-192（设置同项） | 同一概念两个操作入口，信息源不唯一；改设置不知道去哪 |
| P2 | **网关区块 4 张卡平级**，状态卡（最常用）排第三，用户进区块先看到低频的套餐卡 | L122-179（套餐→Token→状态→日志） | 主次不分，高频运维入口被低频配置压住 |
| P3 | **两个日志区分离、交互不一致**：运行日志在「统计」区块（自动刷新+过滤+清空），网关日志在「网关管理」区块（仅手动刷新） | L108-118 vs L170-179 | 排障要跨两个区块切页，工具行为不统一 |
| P4 | **「分析」主题三处分散**：轮换统计（nav-stats，go-rotate 日志视角）、网关用量 perKey（gateway-card gw-body，网关 usage 视角）、运行日志（nav-stats） | L94-106、L431-437、L108-118 | 同一「看数据」诉求拆在 2 个区块，心智负担大 |
| P5 | **无主次与引导**：全部卡片同权重；0 key / 网关未装 / token 未设时仅散落小字提示；首次上手路径不明确 | L74（web 关闭提示）、L405-411（网关未装提示） | 新用户不知道先做什么 |
| P6 | **任务路径断裂**：① 新增 key 后不会自动设为当前（要回表格再点「启用」）；② 复制 token 必须先「显示/隐藏」再看明文再「复制」（`copyToken` 要求 `gwToken.plain` 可见）；③ 套餐切换的结果确认在另一张卡 | L589-596（copyToken 前置检查）、L538-546（切套餐后 refresh 但状态卡在下） | 高频路径多 1-3 步 |
| P7 | **布局未响应式**：`max-width: 860px` 单列，桌面空间利用率低；表格无横向滚动容器，移动端溢出 | L11（.wrap）、L85-88（table 无 overflow 容器） | 桌面浪费、移动不可用 |

### 1.3 兼容边界（测试锁定，规划红线）

`tests/go-rotate-plugin.test.ts` 断言（L627-935）——**以下必须保持存在**：

- `id="main-nav"` + 5 个 `data-nav="overview|keys|gateway|stats|settings"` 按钮 + 5 个 `id="nav-{overview,keys,gateway,stats,settings}"` 区块 + `function switchNav(block)` + `onclick="switchNav('overview')"`。
- 套餐卡：`gw-plan-card` / `plan-go` / `plan-zen` / `plan-apply` / `plan-meta` + `saveGatewayPlan` / `refreshPlans` / `api("/api/gateway/restart", {})`。
- Token 卡：`gw-token-card` / `token-input` / `token-badge` + 5 个 onclick（`genGatewayToken` / `setGatewayToken` / `copyToken` / `toggleTokenMask` / `clearGatewayToken`）+ `refreshGatewayConfig` / `genGatewayToken` / `setGatewayToken`。
- 网关状态卡：`gateway-card` / `gw-badge` / `gw-mcount` / `gw-version` / `gw-start|stop|restart`（onclick `gwManage`）/ `gw-ctl-msg`。
- 其余：`stats-tbody` / `st-total` / `log-auto` / `log-filter` / `data-window`（行内窗口按钮）/ 删除 `confirm`。

**JS 依赖元素（可移动、不可删）**：`refresh()` 引用 `s-current s-avail s-total s-cooldown s-autoweb set-cooldown set-autoweb web-off-btn web-on-btn tbody msg check-hint`；`refreshGateway` 引用 `gateway-card gw-badge gw-current gw-avail gw-rot gw-req gw-mcount gw-version gw-start gw-stop gw-restart gw-ctl-msg gw-body`；`refreshGwLog` 引用 `gwlogview gwlog-src`；`refreshPlans/refreshGatewayConfig` 引用 `plan-* token-*`。

> **结论**：所有改动只能是「整卡移动 / 卡片内部顺序调整 / 加包装容器 / 加 CSS class」；`nav-*` 五个区块 id 不能改（`switchNav` 依赖）。新增 id 一律新前缀，不与既有 id 冲突。

## 2. 新信息架构（IA 决策）

### 2.1 核心决策总表

| 决策点 | 结论 | 一句话理由 |
|---|---|---|
| D1 区块职责 | **5 区块保持**（test 锁定），职责重定义：概览=只读状态面板；Key 管理=主操作区；网关管理=网关运维；统计=分析与日志；设置=全局配置 | 导航结构不动，块内重组，零破坏 |
| D2 概览内容 | **当前 key + 可用/总数 + 网关运行态 + 最近轮换时间 + 冷却窗口(只读) + Web 自动启动(只读)**，做成横向「状态条」；所有编辑/开关按钮下沉到设置与 Key 管理 | 概览是 glance，不是 dashboard 操作台 |
| D3 冷却归属 | 每 key 冷却/独立窗口**行内保留**（已在表格内，最贴近上下文）；全局冷却窗口**只留设置**；概览只读展示全局值 + 「去设置」跳链（复用 `switchNav('settings')`，零新 JS） | 冷却操作是 key 的属性 → 行内；全局窗口是全局配置 → 设置 |
| D4 网关管理 | 拆成**状态主卡 + 配置子卡**两级：状态卡提升为首位（运行徽标/统计/启停/模型/用量 perKey）；套餐卡 + Token 卡并列成「配置」子区；**网关日志卡移出到「分析与日志」** | 状态高频高权重，配置低频并排，日志归日志 |
| D5 统计与日志 | **统一为「分析与日志」**（id 保持 `nav-stats`）：轮换统计 + 运行日志 + 网关日志三卡；**网关用量 perKey 留在网关状态卡**（与 `/api/gateway` 同一请求源，避免双拉取） | 同一请求数据不重复展示；日志类聚合一处 |
| D6 设置 | 全局冷却窗口 + Web 自动启动（**唯一可操作点**）；**不新增**「套餐默认值」概念（当前套餐即当前值，无默认档概念，属后端语义）；不新增 provider_id 编辑（既有设计有意保留，见 Web界面使用.md §7.4#9） | 设置=全局配置；套餐/Provider 是当前值不是默认值 |
| D7 空状态引导 | 引入**3 处空状态横幅**（0 key / 网关未装[已有提示，保留]/ token 未设[已有小字，升级为横幅]）+ 概览首上手线性引导条「① 加 key ② 开网关 ③ 配 token」 | 降低首次上手成本，不改任何 API |
| D8 布局 | 桌面**双列网格**（`max-width: 860 → 1060px`）：网关状态卡 2/3 + 配置卡 1/3；日志两卡并排；移动端单列 + 表格横向滚动容器 | 桌面利用率 + 移动可用性 |
| D9 不做 | 不做多页路由 / 不删功能 / 不引入图表库（用量趋势用 HTML 表格或字符条，不引第三方） | 保持零依赖单页 |

### 2.2 区块 → 卡片 → 元素（新结构树）

优先级标注：**主**=高频/核心操作；**次**=中频配置；**从**=只读/低频/信息。

#### nav-overview 【概览】— 只读状态面板（信息密度：高）

```
状态条 ov-strip（一行横排，桌面 6 格 / 移动 2 列换行）
├─ 当前 key        s-current            [主]  当前生效 key 名
├─ 可用            s-avail + s-total    [主]  availableCount/keyCount
├─ 网关运行态      ov-gw-state [新增]   [主]  「运行中 v1.1.0 / 未运行 / 未安装」+ 徽标（复用 refreshGateway 数据）
├─ 最近轮换        ov-last-rotate[新增] [次]  最近一次轮换时间（复用 refreshStats 数据）
├─ 冷却窗口(只读)  s-cooldown           [从]  全局分钟 + 「去设置」跳链(switchNav('settings'))
└─ Web 自动启动    s-autoweb(只读)      [从]  开/关 + 「去设置」跳链
引导条 ov-hint [新增]
└─ 线性首上手：① 添加 key → Key 管理　② （可选）启动网关 → 网关管理　③ （可选）生成 token → 网关管理
   （空 keyCount 时显示完整引导；有 key 后折叠为一行「当前状态健康」）

#### nav-keys 【Key 管理】— 主操作区（信息密度：高）

```

## 8. 核心 IA 决策总结

1. **5 区块导航不变**（`overview/keys/gateway/stats/settings` 由单测锁定），全部改动发生在区块内部——零导航风险。
2. **概览降为纯只读「状态面板」**：当前 key / 可用 / 网关运行态 / 最近轮换 / 冷却 / Web 自动启动，编辑动作全部下沉到设置与 Key 管理；解决「同一概念双处可操作」的重复。
3. **冷却行内化**：每 key 冷却/独立窗口留在表格行内（最贴近上下文），全局窗口只在设置——冷却不再单独占位。
4. **网关管理两级化**：状态卡提升为主卡（2/3 宽），套餐 + Token 并为配置子区（1/3 宽）——高频运维一眼可见，低频配置并排可操作。
5. **统计统一为「分析与日志」**：轮换统计 + 运行日志 + 网关日志三卡聚合一处（网关日志从网关区块移入），排障不再跨区块；网关用量 perKey 留在状态卡（同一请求源，避免双拉取）。
6. **引入空状态引导**：0 key / 网关未装 / token 未设三处横幅 + 概览首上手线性引导条，新用户 3 步上手。
7. **改动分级清晰**：A 组（纯布局，零 JS）为主，一次提交即可上线；B 组 5 项小 JS 增强（最近轮换 / 网关态 / 空态 / 复制 token 一步化）每项 ≤5 行；C 组后端增强（首个 key 自动 current、7 天用量趋势）为可选低优。
8. **桌面双列 + 移动单列**（1060px 网格 + 表格横向滚动），零依赖、单页、全功能保留。
