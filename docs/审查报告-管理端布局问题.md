## 1. P1（功能错误 / 数据错误渲染）— 3 项

### P1-1 网关日志卡显示原始 JSON（已知问题 1，已定位根因）

- **现象**：统计区块「网关日志」`pre#gwlogview` 显示 `{"lines":["[2026-08-16T14:17:16.549Z] [gateway] 🚀 zen-gateway 启动…","…","…"],"total":4}` 原始 JSON 字符串，而非逐行可读文本。来源标注显示「来源: gateway /api/gateway/log」（说明走了新端点分支）。
- **复现**：打开页面 → 统计 → 网关日志卡（或点「刷新」）。100% 复现。
- **根因**：`go-rotate.ts` `gatewayLog()`（L559-570）主分支用 **`r.text()`**（L563）取回 zen-gateway `/api/gateway/log` 的**响应体原文**；而 gateway.mjs 该端点返回的是 `getLogRing()` 的 **JSON 结构** `{ lines: string[], total: number }`（gateway.mjs L135-138，路由 L1668-1669）。`r.text()` 拿到 JSON 序列化字符串直接作为 `text` 返回 → 前端 `refreshGwLog()`（L1642-1656）`pre.textContent = r.text` 原样展示。**两侧契约不匹配**：go-rotate 侧假设端点返回纯文本，gateway 侧返回 JSON。
- **修复建议**（改 `gatewayLog()`，约 3 行）：
  ```ts
  const j = await r.json().catch(() => null)
  if (j && Array.isArray(j.lines)) return { ok: true, text: j.lines.join("\n"), source: "gateway" }
  ```
  回退分支 `runGatewayCtl(["logs","300"])` 返回纯文本，无需改。改后须同步插件单测（`tests/go-rotate-plugin.test.ts` 对 `gatewayLog` 若有 mock 断言需按新解析行为更新）。

### P1-2 桌面宽屏页面横向溢出 5140px（P1-1 连锁 + 结构性缺陷）

- **现象**：桌面 1280px 视口下 `document.body.scrollWidth = 5140` vs `clientWidth = 1032` —— **页面横向溢出 4 倍**，出现整页横向滚动条；统计区块 `.log-row` 两列卡片实际渲染宽 **1433px + 3670px**（远超 `.wrap` 1060px 与 `.log-row` 992px 容器）。
- **复现**：桌面（>720px）打开页面 → 统计区块。移动端（390px）实测**无此问题**（断点 <720px 转单列）。
- **根因**（两层）：
  1. **直接触发**：P1-1 的网关日志 JSON 单行 **475 字符**（`{"lines":[...],"total":4}` 一整行无换行）+ 运行日志测试污染行 **184 字符**（`__RING_TEST_` 长行）。
  2. **结构性缺陷**：`.log-row`（CSS L1006 `grid-template-columns: 1fr 1fr`）的 grid item（`.card`）未设 `min-width: 0` → grid item 默认 `min-width: auto` 取内容最小宽度 = pre 中最长行宽度 → **pre 自身的 `overflow: auto`（L1121-1123）被 grid min-width 覆盖，无法内部滚动**，track 被撑爆。
- **影响**：桌面用户看统计区块必须左右拖动页面；`gwlogview` 3670px 宽不可读。
- **修复建议**（两处，均小）：
  1. P1-1 修复后 JSON 行消失（最长行回到正常日志行）。
  2. 结构性防御：`CSS .log-row > .card, .gw-config-grid > .card { min-width: 0 }`（grid item 允许收缩，pre 恢复内部 `overflow-x: auto` 滚动）。这是**根治**，防任何未来长行（如超长日志）复发。

### P1-3 运行日志 / 轮换统计被测试记录污染 80%（已知问题 2，专项结论见 §4）

- **现象**：统计区块「运行日志」`pre#logview` 300 行中 **244 行（81%）是测试残留**（`__RING_TEST_1~250`、`__RING_FIFO_*`、`/tmp/gort-plugin-test-*` 路径、`/tmp/zen-gateway-unittest-*`、`fake zen-gateway start/stop/restart`）；「轮换统计」表格显示 **234 次总轮换**及 `a / act1~3 / b / bad / good` 等**测试假 key**（真实配置仅 1 个 `test` key）。概览「最近轮换 10:59:44」也是测试数据。
- **复现**：打开页面 → 统计区块。100% 复现。
- **性质判定**：**页面无责**——页面如实展示了共享日志文件内容；根因在**测试隔离缺陷**（详见 §4 专项）。
- **页面层面附加影响**：真实日志（如用户真实轮换记录）被测试刷屏**挤出 300 行显示窗口**，排障时看不到真实记录；`parseStatsLog` 统计也被污染（假 key 轮换/冷却计数）。

## 2. P2（布局缺陷 / 体验问题）— 7 项

### P2-1 设置 / 统计区块操作成功反馈不可见（showMsg 写入隐藏 #msg）

- **现象**：设置区块点「开启 Web」/「编辑」全局冷却窗口、统计区块点「清空日志」，操作**成功但无任何可见反馈**（按钮状态变化是唯一线索）。
- **复现**：设置区块 → 点「开启」→ confirm 取消即可观察（或直接看代码路径）。实测 `showMsg('Web 已重新启动…')` 后 `#msg` 的 boundingRect 全 0（元素在 `display:none` 的 `#nav-keys` 内）。
- **根因**：`showMsg/showErr`（L1454/L1449-1453）只写 `#msg`（位于 Key 管理卡，`nav-keys` 默认隐藏）。`showErr` 有 toast 兜底（P1-3 修复已做），但 **`showMsg` 无任何全局兜底**。受影响调用：`webOn`（L1432）、`editGlobalWindow`（L1499）、`clearLog`（L1801）、`gwManage`（L1632，该处另有 `gw-ctl-msg` 可见，影响小）、`saveGatewayPlan`（有 `plan-msg` 可见，不受影响）。
- **修复建议**：`showMsg` 增加 toast 输出（复用 `toast(m, "success")`，与 showErr 对称）；或各操作区块本地化消息容器。约 1 行。

### P2-2 「当前状态健康」文案夸大（引导条语义失真）

- **现象**：概览引导条 `ov-hint` 只要 `keyCount > 0` 即显示「当前状态健康。」——即使网关未运行、所有 key 冷却中/无效/余额不足。
- **复现**：1 个 key + 网关停止（或全部冷却）时概览仍显示「当前状态健康」。
- **根因**：`refresh()` L1346-1349 仅按 `st.keys.length` 切换 `ov-hint-full`/`ov-hint-min`，未结合 `availableCount`、`last_status`、网关态。
- **修复建议**：`refresh()` 判定升级为 `keyCount > 0 && availableCount > 0` 才显示「健康」；否则显示「有 key 但当前不可用」提示（或联动 `refreshGateway` 的网关态）。约 3 行。

### P2-3 Key 表格 5s 全量重建打断交互（审计 P2-2，仍未修）

- **现象**：`refresh()` 每 5s 无条件 `tbody.innerHTML=""` + 逐行重建 + 6 个 `querySelectorAll` 重绑事件。用户在表格 hover/准备点击时，按钮节点被替换，事件绑定窗口期内点击丢失。
- **根因**：`go-rotate.ts` L1350-1398。审计基线已记录（§6 P2-2），本轮重构 CSS 未触及（设计规范 §4 明确「CSS 不做 diff 渲染」）。
- **修复建议**：JS 重构时按数据变化守卫（keys 长度/内容 hash 未变则跳过重建）；或 diff 更新。本轮不做可接受（单 key 场景影响小）。

### P2-4 隐藏区块持续轮询（审计 P2-1，仍未修）

- **现象**：`refreshStats`（10s）/`refreshGateway`（15s，内部 4 路子请求）/`refreshPlans`（30s）在对应区块隐藏时仍常驻拉取；默认常驻 ≈24 请求/min，全开 ≈44/min。
- **根因**：L1808-1812 四个 interval 全部常驻。设计注释 L1658「全部区块常驻 DOM 避免重复拉取」——属设计张力，非 bug。
- **修复建议**：切区块时启停 interval（`switchNav` 内控制）或按可见性节流。低优先。

### P2-5 轮询失败反复弹 toast 污染（审计 P2-7，仍未修）

- **现象**：`refresh()` 等 5s 轮询 catch → `showErr` → 写 `#msg` + **全局 toast**，每 5s 反复弹出；覆盖用户刚看到的操作结果（错误时）。用户正在操作时被错误 toast 打断。
- **根因**：L1399 `catch (e) { showErr(e.message) }`。
- **修复建议**：轮询失败走静默/角落降级（如仅更新 `s-*` 为「—」），操作类错误才 toast。与 P2-1 同属消息体系重构。

### P2-6 Key 表操作列 6 按钮在窄列换行撑高

- **现象**：非 current + 冷却中 + 有独立窗口的 key，操作列最多 6 按钮（启用/清除冷却/窗口/清窗/编辑/删除），实测当前 4 按钮即占 **306px**；`table min-width:720px` 下操作列约 326px，6 按钮必然 flex-wrap 换行、行高翻倍。多 key 场景表格纵向膨胀。
- **根因**：L1378-1387 按钮无紧凑化；`.actions` 有 flex-wrap（L1004）但不限行数。
- **修复建议**：`.actions button` 已由设计系统 `.sm`（26px/8px padding）紧凑化，但按钮**数量**多；可考虑合并冷却/窗口为下拉、或允许横向滚动（操作列 `white-space: nowrap` + 表横向滚动）。低优先。

### P2-7 健康徽章色语义不符（invalid/nobalance/error 仍为琥珀）

- **现象**：Key 表状态徽章中「key 无效 / 余额不足 / 限流 / 异常」全部用 `.b-cooling` 琥珀色（与「冷却」同色），无法视觉区分「待冷却恢复」与「key 已废/需充值」。
- **根因**：`refresh()` L1357 `tip()` 硬编码 `b-cooling`；设计规范 §2.2 已预置 `.b-invalid` 红色徽章与映射表，**CSS 就绪但 JS 未接线**（明确标注「待 B 组修」）。
- **修复建议**：`tip()` 按 `statusLabel` 映射 class：`invalid/nobalance/error → b-invalid`，`limited → b-warn`，`ok/cooling → 现状`。约 3 行。

## 4. 专项结论：测试污染（已知问题 2）

### 结论：**测试隔离缺陷，非页面缺陷**。页面如实展示共享日志文件，但数据已被测试刷屏到不可用。

### 根因（代码级）

| 层 | 位置 | 问题 |
|---|---|---|
| go-rotate.ts | **L45** `const LOG_FILE = "/tmp/opencode-go-rotate.log"` | 模块级常量，**无 env 覆盖**（对比：`CONFIG_FILE`/`AUTH_FILE` 已有 `GOROTATE_*` 覆盖） |
| go-rotate.ts | L96-99 `log()` → `appendFileSync(LOG_FILE, …)` | 无条件写共享日志；插件单测（`GOROTATE_CONFIG_FILE/AUTH_FILE` 隔离了配置）**未隔离日志**，测试进程的 `log()` 全部写入真实文件 |
| gateway.mjs | **L65** `const LOG_FILE = "/tmp/opencode-go-rotate.log"` | 与插件**共用同一日志文件**；`ZEN_TEST=1` 单测（`__RING_TEST_1~250`、`__RING_FIFO_*`）同样写入 |
| gateway.mjs | L130 `appendFileSync(LOG_FILE, line)` | 同上 |

### 量化危害（实测）

- 日志文件 5481 行，**测试记录 4403 行（80%）**，真实 1078 行（20%）。
- **页面 logTail(300) 显示窗口内 244/300（81%）是测试记录** —— 真实日志（用户真实轮换/冷却）被挤出，**排障不可用**。
- 轮换统计被污染：`parseStatsLog` 从同一日志解析 → 表格显示测试假 key（`a/b/good/bad/act1-3`）+ 234 次虚假轮换。
- 测试刷屏还加速 `rotateLogIfNeeded()` 1MB 轮转（L79-86），真实记录被归档挤掉。

### 修复方向（按优先级）

1. **推荐**：`LOG_FILE` 支持 env 覆盖 —— go-rotate.ts 加 `process.env.GOROTATE_LOG_FILE || "/tmp/opencode-go-rotate.log"`；gateway.mjs 加 `process.env.ZEN_LOG_FILE || …`（与既有 `ZEN_CONFIG/ZEN_AUTH_FILE` 同模式，生产不设行为不变）。插件单测 import 前设 `GOROTATE_LOG_FILE` 指向临时路径；gateway 单测设 `ZEN_LOG_FILE`。**改动各 1 行 + 测试 2 处，根治。**
2. 清理存量污染：`rm /tmp/opencode-go-rotate.log*`（日志非关键数据，重启即重建）。
3. 页面侧**不建议**加过滤（日志要真实；过滤会掩盖真实轮换记录），污染根除后自愈。
4. 长期：`tests/` 统一测试隔离基座（GOROTATE_CONFIG/AUTH/LOG 三件套一次性封装），防止未来新测试再漏。
