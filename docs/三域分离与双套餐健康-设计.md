# 三域分离 + 双套餐健康检查 + Web 4 区块重构设计

> 2026-08-17 用户需求 + brainstorming 澄清后定稿。契约文档，实施 team 必读。
> 前置：`docs/双域独立轮换-设计.md`（已交付，网关域已独立；本设计在其上扩展为三域）

## 需求（用户原话归纳）

1. 网关与 TUI **分成两个页面**分别设置，互不干扰；**Key 管理页面可以看到 TUI 和网关健康情况**
2. **zen 与 go 套餐轮换各是各的独立处理**（不再是 TUI 一刀切）
3. 每把 key 增加 **zen / go 套餐情况检查项**（是否可使用等健康情况）

## 决策（已确认）

- **三域模型**：`zen`（opencode 免费档 provider `opencode`，模型 hy3-free）/ `go`（套餐 provider `opencode-go`，模型 hy3）/ `gateway`（网关 upstream go 档，上轮已独立）。三域各自独立 current + 冷却 + 轮换，互不干扰
- **健康检查**：每 key 双端点探测——zen 档 `https://opencode.ai/zen/v1`（hy3-free）+ go 档 `https://opencode.ai/zen/go/v1`（hy3），最小请求 max_tokens=1；每 key 存双状态；手动「检查」触发（现状 /api/keys/check 扩展）
- **Web 4 区块导航**：Key 管理 / TUI / 网关 / 统计（单测「3 区块」断言同步更新）

## Schema 演进（并列字段，向后兼容，零迁移）

```jsonc
{
  "current": "act1",                 // zen 域游标（字段名不变 = 现状语义，零迁移）
  "current_go": "act1",              // 新增：go 套餐域游标。读侧兜底 current_go ?? current
  "current_gateway": "act1",         // 网关域（已交付）
  "cooldown_minutes": 300,           // 共享窗口配置（三域同用，不分裂）
  "keys": [{
    "name": "act1", "key": "sk-...",
    "cooldown_minutes": 30,               // 共享：该 key 独立窗口
    "cooldown_until": null,               // zen 域冷却（现状）
    "cooldown_until_go": null,            // 新增：go 域冷却
    "cooldown_until_gateway": null,       // 网关域冷却（已交付）
    "last_status": null,                  // zen 域健康状态（现状）
    "last_status_go": null,               // 新增：go 域健康状态
    "last_checked_zen": null,             // 新增：zen 探测时间（ISO）
    "last_checked_go": null               // 新增：go 探测时间（ISO）
  }]
}
```

- 旧配置零迁移：`current`/`cooldown_until`/`last_status` = zen 域（现状字段天然对应免费档 provider `opencode`）
- `cooldown_minutes`（全局/每 key）共享不分裂

## 各组件改动面（按团队分工）

### Team A — 插件 go-rotate.ts（三域 + 健康检查 + Web 4 区块）

1. **Schema**：`Config.current_go?` + `KeyEntry.cooldown_until_go/last_status_go/last_checked_zen/last_checked_go`；loadConfig 归一化；读侧兜底 `current_go ?? current`
2. **chat.headers 分流**（核心）：
   - `pid === "opencode-go"`（或 endsWith 精确匹配）→ 注入 **go 域** current key
   - `pid === "opencode"`（或 includes("opencode") 但非 opencode-go）→ 注入 **zen 域** current key
   - 非 opencode 一律不注入（现状红线不变）
3. **event 钩子**：sessionProvider 记录的 pid 精确判断 session 属于 zen 域还是 go 域 → `rotate(domain)` 按域轮换：
   - `rotate(msg, err, domain: "zen"|"go")`：冷却写对应域 `cooldown_until`/`cooldown_until_go`；`pickNext(cfg, domain)` 按对应域冷却筛选；current 写对应域字段；`syncAuth` 仅 zen 域轮换时执行（**go 域轮换不写 auth.json**——auth.json 单槽代表 zen 免费档现状语义？**主线程裁定**：auth.json 继续由 zen 域维护；go 域与网关域一样不碰 auth.json）
4. **健康检查双端点**：`probeKey(key, domain)` 改造——zen 端点（hy3-free）/ go 端点（hy3）；`/api/keys/check {name?, domain?: "zen"|"go"|"all"}`（默认 all=双端点）；写 `last_status_zen`/`last_status_go` + `last_checked_*`；GET 改为不再触发探测（现状 GET/POST 均可触发——顺手修掉，仅 POST）
5. **statusPayload 三域**：`current`（zen）+ `current_go` + `current_gateway`；每 key：`cooldown_until/cooldown_until_go/cooldown_until_gateway` + `last_status/last_status_go` + `last_checked_zen/last_checked_go` + `isCurrent/isCurrentGo/isCurrentGateway`
6. **Web API**（缺省 domain=zen，向后兼容）：`/api/current {name, domain?: "zen"|"go"|"gateway"}`；`/api/cooldown {name, minutes, domain?}`；`/api/rotate {domain?}`（默认 zen）——网关域 rotate 不支持（CLI 管）
7. **Web 4 区块导航**：
   - **Key 管理**（nav-keys，缺省区块）：健康总览条（TUI-zen 当前/健康、TUI-go 当前/健康、网关运行态 + 各域可用 key 数）+ key 列表（双套餐健康列「zen: ✓/✗ go: ✓/✗」+ 每 key 「检查」按钮 + 三域使用/冷却按钮 + 徽标）
   - **TUI**（nav-tui，新增）：zen / go 两个子区块（各自：当前 key、冷却中 key 列表、手动轮换按钮、冷却设置）
   - **网关**（nav-gateway）：现状网关设置整体迁入（原 nav-settings 网关部分 + 使用方式卡 + web on/off）
   - **统计**（nav-stats）：不变
   - 原 nav-settings 剩余（主题等）归属：主题按钮已在页头不动；设置项随功能归位
   - 单测「3 区块」断言 → 4 区块同步更新
8. **插件单测**：三域用例（注入分流 zen/go、rotate 按域、双端点健康检查状态、statusPayload 三域、Web domain 参数矩阵、auth.json 仅 zen 域写）

## 风险与边界

- **注入分流依赖 providerID 精确值**：`opencode-go` vs `opencode`——若真实环境 providerID 有其它形态（如带后缀），`isGoProvider(pid)` 判定函数需容错（endsWith("opencode-go") 或 === "opencode-go"）。实现后真实验证注入对象
- **物理配额共享**：同一 key 双套餐状态独立探测，但配额物理共享（go 用爆 zen 免费档也可能受限）——探测如实展示，不强行联动
- **轮换候选筛选只看冷却（现状语义）**：健康状态仅展示 + 手动 check 更新，不参与 pickNext 筛选（避免状态过期误判）
- **auth.json 归属**：仅 zen 域轮换写 auth.json（现状语义 = 免费档主用）；go/网关域不碰
- 测试铁律：GOROTATE_CONFIG_FILE/GOROTATE_AUTH_FILE/ZEN_CONFIG/ZEN_AUTH_FILE/临时 HOME 隔离；真实 8899/18888/真实配置只读
