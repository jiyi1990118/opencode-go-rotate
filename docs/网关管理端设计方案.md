# Web 网关管理端设计方案

> 日期：2026-08-16
> 性质：**架构与产品设计文档（只输出设计，不写生产代码）**，作为并行开发 teams 的契约
> 目标：把「go/zen 套餐切换」「网关访问 token 定义」「现有 key 管理」三件事在 8899 Web 面板上统一可视化，做成管理端。

## 0. 背景与需求翻译

用户三条需求逐条翻译成技术需求：

| 用户原话 | 技术需求 |
|---|---|
| **「go / zen 套餐网关切换」** | Web 面板能切换 gateway.mjs 连接的上游端点（`https://opencode.ai/zen/v1` 免费档 vs `https://opencode.ai/zen/go/v1` 订阅档），切换后模型表 / 默认模型 / 探测模型随套餐变化，并通过重启网关生效。 |
| **「网关 key 的定义（提供给其它 agent 使用）」** | Web 面板能生成 / 编辑 / 复制 / 删除一个**网关访问 token**（供 claude code / codex / cursor 连网关时携带），token 持久化到配置、启动读取，替代当前硬编码的 `ZEN_GATEWAY_TOKEN` env（launchd plist 未注入）。 |
| **「把所有功能都在 Web 上可视化操作，做成管理端」** | 把现有 CLI/Web 已能做的（key 增删改、冷却、轮换、启停、日志、统计）+ 本次新增的网关配置（套餐 + token）全部收进 Web 面板，做成带主导航的多区块管理端。 |

## 2. 配置模型（核心决策）

### 2.1 配置归属：新增独立 `gateway-config.json`（推荐）

**决策：网关配置（套餐 + token）放独立文件，不放 go-keys.json。**

| 候选 | 方案 | 结论 |
|---|---|---|
| **a) 扩展 go-keys.json** | 加 `gateway: {plan, token}` 顶层字段；`mutateConfig` 已保留扩展字段不会丢 | ❌ **不推荐** |
| **b) 独立 `gateway-config.json`** | 网关启动读、Web/CLI 写；改了重启生效 | ✅ **推荐** |

**理由（为什么 b 优于 a）：**
1. **职责分离**：`go-keys.json` 是「key 轮换」运行期高频读写配置（每次轮换 / 注入 / 状态都要锁 + 读写）；`gateway-config.json` 是「网关服务」低频静态配置（只在切换套餐 / 改 token 时变一次）。两类生命周期与并发模型完全不同，塞一起会让低频写与高频读写争同一把 `go-keys.json.lock`，且状态视图（`statusPayload`）每次都要多解析一份无关字段。
2. **敏感凭据隔离**：token 是访问凭据。独立文件可单独设 `0600` 权限，且**不会**被插件 `loadConfig` 当「扩展字段」读进内存反复序列化往返（go-keys.json 的扩展字段机制虽能保留 token，但会让它出现在每个读 go-keys.json 的地方）。独立文件只有 gateway.mjs / go-rotate.ts / CLI 的网关配置写路径会碰它。
3. **向后兼容 / 干净回退**：文件不存在时 gateway 完全回退到现有 env（`ZEN_UPSTREAM_BASE` / `ZEN_DEFAULT_MODEL` / `ZEN_GATEWAY_TOKEN`）→ 默认值。**老用户 / 纯 env 部署零迁移**。go-keys.json 方案做不到「文件缺失即回退」的干净分层（字段可能半存在）。
4. **避免锁纠缠**：gateway 读配置在启动热路径，若依赖 go-keys.json 会在每个请求的 `gatewayAuth` / `mapModel` 里读文件，违背「启动时固化 + 请求走内存」的性能原则。

**文件位置**（与 gateway 安装目录同族，含凭据故放 `.local` 数据目录）：
```
~/.local/share/zen-gateway/gateway-config.json
```
**测试隔离**：`ZEN_GATEWAY_CONFIG` env 覆盖路径（生产不设行为不变，与 `ZEN_CONFIG` / `ZEN_AUTH_FILE` 对称）。

**Schema：**
```jsonc
{
  "plan": "go",                      // "go" | "zen"
  "token": null,                     // 网关访问 token；null = 不启用鉴权（= 原 env 未设）
  "token_set_at": null               // 记录 token 生成/编辑时间（审计，可空）
}
```

**优先级（从高到低）**，保证测试隔离与老部署兼容：
```
ZEN_UPSTREAM_BASE / ZEN_DEFAULT_MODEL / ZEN_GATEWAY_TOKEN (env，测试/特殊部署)
  → gateway-config.json 的 plan/token（Web/CLI 写入的运行时配置）
  → 内置默认（go / https://opencode.ai/zen/go/v1 / hy3 / 无 token）
```

### 2.2 生效机制：**重启**（非热切换）

**决策：套餐 / token 变更统一走「写配置 → 重启网关」一次事务，不做热切换。**

**热切换成本评估（gateway.mjs）：**
- `UPSTREAM_BASE` → `GO_API` / `MODELS_API` 在模块顶层拼出（L61-63），被 `upstreamOnce`（L827）/ `fetchModels`（L461）直接引用；
- `DEFAULT_MODEL`（L65）被 `mapModel`（L480-485）每次请求读取；
- `TOKEN`（L1663）被 `gatewayAuth`（L936）每次请求读取；
- `refreshDynamicModels`（启动时跑一次）拉模型表。
热切换需把这些常量改为「内存可变变量 + 请求时动态取值 + 切换时重新拉模型表 + 重置探测定时器」，改动触及协议热路径与并发读取，回归风险高（本项目已多次因热路径改动出 bug）。

**为什么重启更优：**
1. **低频操作**：套餐 / token 变更属「管理动作」，用户不会频繁切换，秒级重启可接受。
2. **天然一致**：换上游 base 本质需要「重拉模型表 + 重置探测定时器 + 刷新默认模型」，重启一次到位，无需处理「切换瞬间的 in-flight 请求」边界。
3. **复用已有能力**：`POST /api/gateway/restart`（execFile 调 bash 脚本，幂等 + 15s 健康等待）已实现，Web 只需「写配置 → 调 restart → 拉新 /api/gateway/status 确认」。
4. **架构决策延续**：整合设计 §3 已确立「网关管理操作一律走 bash 脚本、不内嵌 start/stop、避免进程自杀」。

> 热切换留作 **Phase 2 可选优化**（§8），仅在用户反馈「切套餐要重启不可接受」时再评估 refactor 成本。

## 3. 套餐定义

基于 `docs/zen-model-research.md` 已核实的官方结论：

| 项 | zen 免费档 | go 订阅档 |
|---|---|---|
| `plan` | `"zen"` | `"go"` |
| 上游 base | `https://opencode.ai/zen/v1` | `https://opencode.ai/zen/go/v1` |
| 默认模型 | `hy3-free` | `hy3` |
| 内置兜底模型表 | `ZEN_MODELS_ZEN`（免费档：big-pickle / deepseek-v4-flash-free / mimo-v2.5-free / hy3-free / laguna-s-2.1-free / nemotron-3-ultra-free / nemotron-3.5-lightning-free） | `ZEN_MODELS_GO`（现有 26 个，hy3 / deepseek-v4-flash / glm-5.2 等） |
| 模型表来源 | `/v1/models` 动态拉取，失败回退内置表 | 同左 |
| key 是否通用 | ✅ 同一 opencode key 双端点都可用（research §2.1 已证实） | ✅ 同左 |
| 合规注意 | 免费档可能用 prompt 训练，敏感代码勿用 | 个人自用合规，转售违反 ToS |

**关键事实（设计依赖，已核实）：**
1. **同一 key 同时用于 Zen 和 Go 两端点**（`docs/zen-model-research.md` §2.1：Docker Docs / shravanbhati 一致佐证）。→ 切换套餐**不需要换 key**，只是换上游 base + 默认模型。
2. **模型 ID 因档位不同**：`hy3`（Go）vs `hy3-free`（Zen）。→ 默认模型必须随套餐变，不能共用。
3. **免费模型名单会变**：以 `/v1/models` 实时返回为准，内置表只是兜底。→ 切换后必须触发重新拉 `/v1/models`。
4. **探测模型随套餐变**：`probeKey` / `ZEN_PROBE_INTERVAL_MIN` 的主动探测用 `hy3`（Go）。切到 zen 档应改用 `hy3-free` 探测（research §「对 go-rotate 的意义」明确「探测别混用」）。→ gateway 探测定点改用「当前套餐默认模型」。

**运行时数据模型（gateway.mjs 内部）：**
```js
// 由 gateway-config.json 的 plan 字段决定；env 优先
const PLAN = { id, upstreamBase, defaultModel, builtinModels }  // 见 §2.1 优先级
let ACTIVE_PLAN   // 内存可变（启动固化一次）
```

## 5. API 契约

### 5.1 新增路由（go-rotate.ts handleWeb）

| Method | Path | Body | Response | 说明 |
|---|---|---|---|---|
| GET | `/api/gateway/plans` | - | `{plans:[{id:"go",upstreamBase,defaultModel,modelCount},{id:"zen",...}]}` | 套餐清单（含各档内置模型表 + 默认模型），供前端渲染两档 meta |
| GET | `/api/gateway/config` | - | `{plan, token: 掩码|null, authEnabled:boolean, tokenSetAt:null|string}` | 读回网关运行时配置（token 掩码，绝不返回明文） |
| POST | `/api/gateway/config` | `{plan?:"go"\|"zen", token?:string\|null}` | `{ok:true, needsRestart:true}` | 写 gateway-config.json；`plan` / `token` 至少给一个；`token:null` = 清除（关鉴权）；成功后前端**必须**再调 restart 才生效（API 只落盘不重启，职责分离） |

> **职责分离说明**：`/api/gateway/config` **只写文件不重启**。重启由前端显式调既有 `POST /api/gateway/restart`。理由：① 保持「写配置」与「启停」两个事务独立，用户可先改多个配置项再一次性重启；② 复用既有 restart 幂等 + 健康等待，不新增重启逻辑副本。

### 5.2 复用既有（不新增）
- `POST /api/gateway/restart`（既有，重启生效）
- `GET /api/gateway`（既有，扩展 meta 含 `plan`/`authEnabled` 字段，向后兼容）
- `GET /api/gateway/log`、`POST /api/gateway/{start,stop}`（既有）

### 5.3 gateway.mjs 新增只读端点（供 go-rotate 拉套餐态）
| Method | Path | Response | 说明 |
|---|---|---|---|
| GET | `/api/gateway/status` | 现有字段 + `plan` + `upstreamBase` + `defaultModel` + `authEnabled` | 扩展既有只读端点（已返回 upstreamBase/defaultModel，补 `plan`/`authEnabled`） |

> gateway 侧**不需要**新增写端点（套餐/token 由 go-rotate Web 直接写 gateway-config.json 文件，gateway 只在启动/重启时读取）。保持「gateway 只读 + 管理面在 go-rotate」的既有架构。

## 6. 鉴权方案（token 管理）

### 6.1 生成规则
- 随机 hex 32 字节（`crypto.randomBytes(32).toString("hex")`，64 字符），无易混淆字符问题（hex 全集 `0-9a-f`）。
- 生成 / 编辑后写 `gateway-config.json.token` + 记录 `token_set_at`。

### 6.2 显示与复制
- 前端默认**掩码**显示（`前4****后4`，复用 `maskToken` 语义），「显示/隐藏」toggle 才明文。
- 复制走 `navigator.clipboard.writeText`，成功后提示「已复制」。
- 明文 token 仅在「显示」态出现在 DOM，其余时刻前端只持有掩码。

### 6.3 gateway 鉴权读取改动
- `gatewayAuth(req)`（L935）：`process.env.ZEN_GATEWAY_TOKEN` → 改为「启动时从 gateway-config.json 读入内存的 `ACTIVE_TOKEN`」（env 优先，见 §2.1 优先级）。逻辑本身（Bearer / x-api-key 双匹配）不变。
- 未设 token（`ACTIVE_TOKEN` 为空 / null）→ 鉴权关闭（`return true`），与现状一致。

### 6.4 单 token vs 多 token（决策）
**单 token**。理由：
1. 本机 / 内网个人网关，token 只做「访问控制」不区分「用户」，一个足够。
2. 多 token 需 token→权限映射，是过度设计（无此需求）。
3. Schema 用 `token`（单值）+ `token_set_at`，字段扁平；将来若要多 token，扩展为数组是向后兼容的（新增字段不破坏）。

## 10. 风险与注意事项

| 风险 | 缓解 |
|---|---|
| 切套餐后模型表 / 默认模型不对（如仍用 Go 的 hy3 探测 zen 档） | Team A 确保 `ACTIVE_PLAN` 覆盖 `mapModel` + 探测定点 + `refreshDynamicModels` 的 base；切档后强制重拉 `/v1/models` |
| 免费档数据可能被训练（ToS） | 文档明示「敏感代码勿用免费档」，Web 套餐切换卡加一句风险提示 |
| 免费名单会变 | 内置表仅兜底，以 `/v1/models` 为准；status 显示「模型数」供用户确认 |
| token 明文泄漏（日志 / DOM / 复制） | 掩码默认、`node --check` 断言无明文、gateway 日志用 `maskToken` |
| 改配置未重启 → 不生效困惑 | API 返回 `needsRestart:true`，前端 applyPlan 自动串 restart 并提示 |
| Web 模板字符串换行 | 沿用 `\\n` 转义纪律 + `node --check` 兜底 |
| 测试碰真实配置 | §8.3 红线 + md5 铁证（本项目血泪教训） |

## 11. 核心决策总结（给主线程）

1. **配置放哪**：独立 `gateway-config.json`（`~/.local/share/zen-gateway/`，0600，`ZEN_GATEWAY_CONFIG` env 覆盖），**不放 go-keys.json**。职责分离 + 敏感凭据隔离 + 文件缺失回退 env/默认零迁移。优先级 `env > 文件 > 默认`。
2. **热切换 vs 重启**：**重启**。套餐/token 变更 = 写配置 → `POST /api/gateway/restart`。低频操作 + 天然一致（重拉模型表/重置探测定时器）+ 复用已有幂等重启。热切换（refactor 常量为内存可变）留 Phase 2 可选。
3. **单 token vs 多 token**：**单 token**。个人网关 token 只做访问控制，多 token 无需求 = 过度设计。Schema 扁平可向后扩展。
4. **套餐事实**：同一 opencode key 双端点通用，切换只需换上游 base + 默认模型（`hy3`↔`hy3-free`），无需换 key；探测模型随档变。
5. **API 清单**：`GET /api/gateway/plans`、`GET /api/gateway/config`（掩码）、`POST /api/gateway/config`（只写不重启，职责分离）+ 复用 `POST /api/gateway/restart`；gateway 侧仅扩展 `GET /api/gateway/status` 补 `plan`/`authEnabled`（无新写端点）。
6. **Team 拆分**：A=gateway.mjs（读配置 + 套餐表 + ACTIVE_PLAN）、B=go-rotate.ts（写配置 + Web 区块 + API）、C=CLI（gateway plan/token）、D=install.sh+plist（生成默认配置、plist 保持 env 空）。
7. **依赖顺序**：A、D 先发；B、C 以 A 契约 stub 并行；A 落地后集成。
8. **隔离红线**：三文件（go-keys.json / auth.json / gateway-config.json）md5 铁证 + `GOROTATE_*`/`ZEN_*` env 隔离 + `ZEN_GATEWAY_BIN` stub 不碰真实服务 + bun homedir 坑。
